# Environment Variables Guide

Complete guide to all environment variables required for Impax Cort3x platform.

## Critical - Required for Production

### Authentication (NextAuth)
\`\`\`bash
NEXTAUTH_SECRET=<generate-with-openssl-rand-base64-32>
NEXTAUTH_URL=https://your-production-domain.com
\`\`\`

### Database (Supabase)
\`\`\`bash
NEXT_PUBLIC_SUPABASE_URL=https://xxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
SUPABASE_JWT_SECRET=<your-jwt-secret>

# PostgreSQL Connection Strings (auto-generated by Supabase)
POSTGRES_URL=postgresql://...
POSTGRES_PRISMA_URL=postgresql://...
POSTGRES_URL_NON_POOLING=postgresql://...
\`\`\`

### Redis Cache (Upstash)
\`\`\`bash
KV_REST_API_URL=https://xxxxx.upstash.io
KV_REST_API_TOKEN=AxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxBCDEFG
KV_URL=redis://default:xxxxx@xxxxx.upstash.io:6379
REDIS_URL=${KV_URL}
\`\`\`

### AI Services (OpenAI)
\`\`\`bash
OPENAI_API_KEY=sk-proj-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
\`\`\`

### Storage (Vercel Blob)
\`\`\`bash
BLOB_READ_WRITE_TOKEN=vercel_blob_rw_xxxxxxxxxxxxxxxxxxxxxxxxxxxxx
\`\`\`

## How to Generate Secrets

### NEXTAUTH_SECRET
\`\`\`bash
openssl rand -base64 32
\`\`\`

### CRON_SECRET
\`\`\`bash
openssl rand -hex 32
\`\`\`

## Vercel Deployment

Add these in Vercel Dashboard → Settings → Environment Variables

**Production Environment:**
- Set `NODE_ENV` to `production`
- Set `NEXT_PUBLIC_VERCEL_ENV` to `production`
- Add all Critical and Important variables

**Preview Environment:**
- Can use same Supabase project or separate dev project
- Recommended to use separate Redis instance
- Set `NODE_ENV` to `production` (Vercel default)

**Development Environment:**
- Use `.env.local` file (never commit to git)
- Can use separate Supabase project
- Set `NODE_ENV` to `development`

## Security Best Practices

1. **Never commit `.env` files to git**
   - Add `.env*` to `.gitignore` (already done)
   - Use `.env.example` for documentation only

2. **Rotate secrets regularly**
   - NEXTAUTH_SECRET: Every 90 days
   - API keys: When team members leave
   - CRON_SECRET: If endpoint is compromised

3. **Use separate environments**
   - Production: Live customer data
   - Staging: Pre-production testing
   - Development: Local development

4. **Monitor usage**
   - Check Supabase quota
   - Monitor OpenAI API costs
   - Watch Redis memory usage
   - Review Vercel bandwidth

## Troubleshooting

### "Supabase client not configured"
- Check `NEXT_PUBLIC_SUPABASE_URL` is set
- Check `NEXT_PUBLIC_SUPABASE_ANON_KEY` is set
- Verify URLs don't have trailing slashes

### "Redis connection failed"
- Verify `KV_REST_API_URL` format
- Check `KV_REST_API_TOKEN` is valid
- Test with `/api/health` endpoint

### "Rate limit errors"
- Redis might be down - check `/api/health`
- Rate limit exceeded - upgrade tier or adjust limits

### "Cron job not running"
- Verify `CRON_SECRET` matches in Vercel cron config
- Check Vercel Cron Logs for errors
- Ensure timezone is UTC

### "Slack alerts not working"
**This is expected if SLACK_WEBHOOK_URL is not configured.**
- Alerts will be logged instead of sent to Slack
- Check webhook URL format is correct if you want to enable it
- Verify the Slack app has permission to post to the channel
- Test the webhook manually with curl

## Getting Help

For issues with environment variables:
1. Check `/api/health` endpoint
2. Review Vercel deployment logs
3. Verify Supabase project settings
4. Contact support with error messages
